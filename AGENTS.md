## Architecture Principles

- **API-first**: All mutating business logic must be callable via HTTP endpoints in `apps/api`. Server Actions in frontend apps are thin proxies that validate UI input and delegate to domain package functions (e.g. `@eleva/auth` provisioning) or the API. Never put business logic only reachable from a Server Action.
- **Agentic-first**: Every API endpoint must be usable by AI agents and external services, not just browser UIs. This means: Bearer token auth alongside session auth, JSON request/response (no form-data-only), deterministic error codes, and discoverable via OpenAPI spec at `GET /openapi.json`.
- **Secure by default**: Every route handler must explicitly declare its auth model. No unauthenticated mutations. Rate limiting required on all non-internal routes (`@upstash/ratelimit` via `apps/api/src/lib/rate-limit.ts`). Zod validation required for all request bodies. See `.cursor/rules/api-first-agentic.mdc`.
- **BotID on public routes**: Any public-facing POST that creates resources or triggers side effects must use Vercel BotID (`apps/api/src/lib/bot-protection.ts`). Agent/M2M routes skip BotID (they authenticate via API key).
- **Domain packages own logic**: `@eleva/auth` owns user/org/membership provisioning and WorkOS interactions. `@eleva/db` owns schema and query helpers. Apps and API routes are thin orchestration layers.
- **No direct DB writes in frontend apps**: Frontend apps (`apps/account`, `apps/app`, `apps/admin`, `apps/expert`) should not import `db()` or `main.*` from `@eleva/db` directly for writes. Use `@eleva/db` query helpers for reads in Server Components, and call domain package functions or `apps/api` for writes.
- **Documented by default**: Every new API endpoint must have its Zod schemas registered in the OpenAPI spec. The spec is the single source of truth for both runtime validation and docs generation.
- **Audit by default**: Every mutating API endpoint and domain function MUST wrap its writes in `withAudit()` from `@eleva/audit`. This inserts an `audit_outbox` row atomically with domain data. The drainer ships rows to the append-only `audit_events` table in the separate audit Neon project. See `.cursor/rules/audit-wiring.mdc` and `packages/audit/README.md`.

## Learned User Preferences

- All HTTP API endpoints (`route.ts`) must live in `apps/api`. Never create API routes in `apps/web` or `apps/app`. Server Actions (`"use server"`) are fine in any app.
- Across the ~10 apps, anything reusable (UI components, helpers, types, constants, hooks, route maps) must live in a `@eleva/*` workspace package, not be duplicated per app. SSOT is mandatory — when in doubt, extract to `packages/` before copying.
- Never leave dead code, legacy files, or empty folders behind when refactoring or removing features — delete them as part of the same change.
- For Next.js v16, Vercel routing/rewrites, WorkOS, Stripe, Drizzle, or any moving SDK, always look up current docs via Context7 (or the `docs-researcher` subagent) before proposing changes — built-in training data is often stale for these libraries.
- Personal organizations are called **Spaces** (e.g. `{firstName}'s Space`), never "Workspaces". New personal orgs default to the first name only, not first + last name.
- In expert/customer-facing copy, refer to end customers as **members** (Eleva is a community), not "patients" or "users". Internal/PHI references in code or docs may still say "patient" where clinically accurate.
- Do not use fragile deep relative paths (`../../../`) in shared package CSS for Tailwind monorepo scanning — follow the official Tailwind v4 / next-forge layered pattern (per-app entry CSS + package-local `@source`).
- Root app layouts should set `suppressHydrationWarning` on both `<html>` and `<body>` — browser extensions (e.g. Grammarly) inject attributes before React hydrates.
- Use cataloged `sonner` via `@eleva/ui` `Toaster` for transient success/error feedback across apps — not inline confirmation banners inside settings cards.

## Learned Workspace Facts

- `docs/eleva-v3/` holds Eleva v3 architecture, ADRs, and environment-matrix port mapping; `apps/docs` hosts Fumadocs API reference at `/docs/api-reference` (from OpenAPI) and hand-written guides under `/docs/guides`. `_context/clone-repo/` stores monorepo-tracked reference snapshots (`eleva-care-app`, `cal.diy`, `next-forge`) with nested `.git` directories removed.
- `@eleva/storage` owns ALL `@vercel/blob` access (boundary lint forbids direct `@vercel/blob` imports outside this package). Two stores: **public** (`BLOB_READ_WRITE_TOKEN`) for avatars and marketing assets, and **private** (`BLOB_PRIVATE_READ_WRITE_TOKEN`) for expert documents, patient reports, and PHI — never store patient/health data in the public store. Entrypoints: `blob-upload-handler` (server), `blob-upload-client` (client). See `.cursor/rules/blob-storage.mdc`.
- Shared dependency versions use **pnpm Catalog** in `pnpm-workspace.yaml` (`"catalog:"` in `package.json`; never hardcode cataloged ranges). `@eleva/api-client` is the typed HTTP client for `apps/api` (not ad-hoc `fetch`). See `.cursor/rules/pnpm-catalog.mdc`.
- Tailwind v4 monorepo CSS: each app has `src/app/styles.css` with `@import "tailwindcss" source(...)` plus `@import "@eleva/ui/globals.css"` and package `sources.css` imports (e.g. `@eleva/dashboard/sources.css`); layouts import `./styles.css`. `@eleva/ui/globals.css` holds theme + UI-only `@source`; workspace packages export local `sources.css`. Each app re-exports `@eleva/ui/postcss.config` in `postcss.config.mjs`.
- `@eleva/audit` owns the transactional outbox pattern. `withAudit(options, fn)` wraps domain writes; `fn` receives a Drizzle `tx` and must call `ctx.emit({ entity, action, entityId, payload })`. Entity/action values are closed unions in `packages/audit/src/types.ts` — extend them when adding new auditable operations. The drainer runs via `POST /workflows/audit-outbox-drainer` on a QStash schedule (twice daily).
- Stripe webhook events follow a **two-file contract**: the dispatcher (`packages/billing/src/server/webhook.ts`, exposed via `POST /webhooks/stripe` route) and the setup script (`infra/stripe/setup-webhooks.ts`). When adding or removing webhook events, update **both** files and re-run `pnpm stripe:setup:webhooks -- --url <ENDPOINT_URL> --apply`. See `.cursor/rules/stripe-webhooks.mdc` and `.cursor/skills/stripe-webhooks/SKILL.md`.
- All apps use Next.js v16's `proxy.ts` convention (not deprecated `middleware.ts`); shared auth-aware proxy logic lives in `@eleva/auth` (`packages/auth/src/proxy.ts`). WorkOS lifecycle/sync is driven by the WorkOS Events API — extend subscriptions and provisioning helpers in `@eleva/auth` (`packages/auth/src/sync.ts`) instead of per-app handlers.
- Cross-app preferences use `.eleva.care` cookies: `ELEVA_LOCALE` (never `NEXT_LOCALE`; SSOT `@eleva/i18n` for next-intl v4) and `ELEVA_THEME` (`light` | `dark` | `system`; SSOT `@eleva/config` + `@eleva/dashboard` with `DashboardProviders`, `ElevaThemeProvider`, `NavThemeMenu`).
- WorkOS has two SSOT layers in `infra/workos`: app capabilities (`rbac-config.json` → `pnpm workos:rbac:generate -- --apply`) and Widget API permissions (`widgets-config.json` → `pnpm workos:widgets:generate -- --apply`; never mix `area:action` slugs with `widgets:*` token scopes). Both scripts dry-run by default — pass `-- --apply` to mutate WorkOS; on promotion, run RBAC apply before widgets apply. `rbac-generate` must not clear all role permissions before rebuild — assign per role in one PUT. `widgets-config.json` `roleWidgetGrants` keys are WorkOS roles `admin`/`member` only; product labels derive from `(org_type, workos_role)` in `@eleva/auth`, not extra WorkOS role slugs. Widget theme/CSS overrides live in `@eleva/dashboard` (`workos-widgets-config.ts`, `workos-widgets-overrides.css`, `ELEVA_WORKOS_WRAPPER_CLASS`); wrap each widget in `ElevaWidgetsProvider`. Map Eleva locale `pt` → WorkOS `pt-PT` (European Portuguese; package `pt.json` is pt-BR). Account settings use `@eleva/ui` `SettingsFieldset`. Horizontal User Profile `DataList` rows require `display: contents` on items — see overrides CSS. See `.cursor/rules/workos-rbac-widgets.mdc`.
- Upstash Redis env vars use Vercel Marketplace's official names verbatim: `REDIS_URL`, `KV_URL`, `KV_REST_API_URL`, `KV_REST_API_TOKEN`, `KV_REST_API_READ_ONLY_TOKEN`. Never rename them in code, `.env.example`, or `turbo.json` `globalEnv`.
- **`@eleva/icons`** is the SSOT for product iconography ([Phosphor Icons](https://phosphoricons.com)). Server layouts use `NavIconName` string literals in nav config (not icon components — RSC-safe); UI chrome imports SSR icons from `@eleva/icons`; client wrappers (`NavIcon`, `ElevaIcon`, `getNavIcon`) from `@eleva/icons/client`. Never `lucide-react` or `@phosphor-icons/react` outside `packages/icons`. See `.cursor/rules/eleva-icons.mdc`.
- Multi-app routing model: end users only ever see `eleva.care` (prod) / `dev.eleva.care` (staging). User-facing apps (`apps/web`, `apps/app`, `apps/expert`, `apps/team`, `apps/academy`) are exposed under the root domain via Vercel rewrites; internal/back-office apps (`apps/account`, `apps/admin`, `apps/api`) use real subdomains but are surfaced through root-domain rewrites where they appear to end users. Org-slug routing uses `~` as the Vercel-style escape hatch between system routes and user-generated slugs (e.g. `/<org-slug>/~/settings`). Per-user account settings live in `apps/account` at `/account/settings` (not `/account/profile`). Global settings surfaces (`apps/account`, `apps/admin`) hide the org switcher — pass `enableOrgSwitcher: false` to `buildDashboardConfig` so the sidebar shows Back → `${GATEWAY_URL}/dashboard` (plain `<a>`, not Next.js `Link`, because `/dashboard` is a Route Handler redirect).
